# ADR-015 — Audit / Correlation Architecture

STATUS=ACCEPTED
TRANCHE=DTH-M9  
DATE=2026-08-13  

## Context
Phase-4 dual-plane reality (root public LIVE; packages Ops LOCAL) frozen at M8C `4545c7b`. Architecture must support secure Ops, durable workflows, and future agents without big-bang rewrite of working public intake.

## Problem
Audit / Correlation Architecture must be decided before implementation so later AuthZ/RLS/workflow work does not accidentally entrench the wrong topology.

## Constraints
- No microservices without need (P20)
- Public intake must not depend on CC/AI (availability)
- RLS ≠ protection from service-role (M8C)
- In-memory controls not production-suitable
- Implementation not authorized in M9

## Options considered
See DTH-M9 evidence report scorecard (Options A/B/C).

## Decision
Canonical audit stream for security, AuthZ changes, external actions, approvals, kill switches, agent/workflow executions, privacy ops. Correlation IDs: lead_id, case_id, event_id, command_id, workflow_id, execution_id, communication_id, approval_id propagated across planes.

## Why
Master Plan audit/evidence requirements.

## Rejected options
Logs-only without correlation; mutable audit without controls.

## Security impact
Forensics and incident response.

## Privacy impact
Audit minimization / retention classes deferred to M10/governance.

## Operations impact
Write path overhead acceptable.

## Migration impact
Exact retention not decided in M9.

## Rollback
Architecture decision can be revised before implementation starts; after impl, follow ADR-specific rollback in implementation tranche.

## Dependencies
M8C baseline; M10 for data/SOT details; M6 does not block this ADR.

## Open questions
Listed in DTH-M9.md where verification still required.

## Evidence references
docs/autonomous-os/evidence-reports/DTH-M8.md, DTH-M8C.md, DTH-M9.md; repo inventory (root app/api, packages/*).
