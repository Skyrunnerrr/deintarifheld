# ADR-034 — Operator vs External Party, Identity Context, Restore Privacy

STATUS=ACCEPTED
TRANCHE=DTH-M10R  
DATE=2026-08-13  

## Context
M10 used PERSON primarily for Clerk/operator mapping and left customer/data-subject linkage under-specified. Restore-after-deletion and marketing-suppression restore were named but not adversarial-hardened. Human RLS requires a non-spoofable DB context that is **not** `auth.uid()` from Supabase Auth (DTH uses Clerk).

## Decisions

### 1) Identity entities
```text
INTERNAL_IDENTITY_ENTITY=OPERATOR_PERSON
EXTERNAL_DATA_SUBJECT_ENTITY=EXTERNAL_PARTY
```
- `OPERATOR_PERSON`: DTH internal human (Clerk-mapped). Roles/capabilities/session registry attach here.
- `EXTERNAL_PARTY`: lightweight contact/subject for customers/applicants (email/phone normalized refs + stable id). Referenced by leads/cases/career — **not** a giant CRM.
- Same email may exist as both operator and external party **without merging identities**.
- Deleting customer/lead data must not delete OPERATOR_PERSON / Clerk mapping.
- Disabling Clerk user must not delete EXTERNAL_PARTY / lead / case records.

Selected contact model: **lightweight EXTERNAL_PARTY** (between lead-owned fields-only and full CRM). Lead/case may still store denormalized contact fields as intake snapshots; EXTERNAL_PARTY supports DSR/dedupe.

### 2) Human DB context pattern
```text
HUMAN_DB_CONTEXT_PATTERN=OPS_API_SET_REQUEST_SCOPED_DB_CONTEXT
```
Flow:
```text
Clerk token → Ops API validates → DTH person mapping → App AuthZ
→ BEGIN
→ set_config('dth.actor_type','PERSON', true)
→ set_config('dth.person_id', <mapped>, true)
→ queries/RLS read current_setting('dth.person_id', true)
→ COMMIT/ROLLBACK
```
- Client-supplied `person_id` / `actor_id` **never trusted**.
- Worker/service: `dth.actor_type=SERVICE` + service id; **no human impersonation** to pass human RLS.
- Agent tools inherit Ops API service path after AuthZ — cannot set arbitrary person context.

### 3) Career purpose boundary
```text
CAREER_DATA_NOT_ACCESSIBLE_TO_SALES_WORKFLOWS
```
Career SoT, access policy, workflow namespace, retention, and authorized operators are distinct from energy sales leads/cases.

### 4) Security-critical audit atomicity
```text
SECURITY_CRITICAL_AUDIT_ATOMICITY_PATTERN=SAME_DATABASE_TRANSACTION_INSERT
```
Security-critical mutations insert audit row in the **same** DB transaction as the mutation. Async AUDIT_WRITER is not allowed for those events. Domain roles may hold INSERT-only on relevant audit tables for this purpose.

### 5) Kill / takeover linearization
```text
KILL_SWITCH_LINEARIZATION_POINT=DISPATCH_AUTHORIZATION_RESERVATION
HUMAN_TAKEOVER_LINEARIZATION_POINT=CONTROL_VERSION_INCREMENT_IN_DB_TXN
```
- Kill / takeover prevent **new** dispatch authorizations after commit of control change.
- Already authorized / in-flight provider calls may complete; system must record and surface IN_FLIGHT / DISPATCH_AUTHORIZED / PROVIDER_CALL_STARTED / RESULT_UNKNOWN.
- Do **not** claim zero external effects after kill unless technically held (they are not, across DB+provider).

### 6) Post-restore privacy reconciliation
```text
POST_RESTORE_PRIVACY_RECONCILIATION=PRIVACY_OPS_LEDGER_PLUS_QUARANTINE_REPLAY
RESTORE_CANNOT_SILENTLY_REENABLE_MARKETING_CONTACT=REQUIRED
```
Durable `privacy_operations` (and suppression records) with external/redundant copy or export of operation ids. After any restore: production remains quarantined until privacy ops + marketing suppressions are replayed/reconciled.

### 7) Raw JSONB
```text
LONG_LIVED_UNSTRUCTURED_PII_IS_NOT_CANONICAL_SOT
```
Lead `payload` jsonb is **transition** / SHORT_OPERATIONAL at most; structured columns are SoT. Workflow/agents must not treat raw jsonb as durable truth. Deletion/DSR must cover jsonb and eventually eliminate long-lived unstructured PII.

### 8) Outbox intent integrity
```text
DISPATCHED_EXTERNAL_EFFECT_MATCHES_COMMITTED_INTENT
```
Outbox binds to immutable/versioned intent (e.g. communication_version_id + content hash + policy decision ref), not mutable draft ids alone.

### 9) Provider unknown delivery
Support `DELIVERY_UNKNOWN`. No blind retry of irreversible effects; use provider idempotency / status lookup / webhook / manual reconcile per adapter capability flags.

### 10) AI fact precedence
```text
CUSTOMER_PROVIDED > HUMAN_VERIFIED > PROVIDER_DERIVED > AI_PROPOSED
```
AI never silently overwrites verified/customer facts; conflicts explicit.

## Rejected
- Overloading OPERATOR_PERSON as customer SoT
- Trusting body `person_id`
- Async-only security audit
- Claiming kill is cross-system atomic with providers
- Raw jsonb as permanent SoT

## Open questions
Exact EXTERNAL_PARTY fields; privacy ledger offsite medium; FORCE RLS rollout — M11/legal as applicable.

## M10F FREEZE
STATUS=ACCEPTED. Binding for implementation. No SQL in this tranche.
