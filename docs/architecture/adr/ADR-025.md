# ADR-025 — Outbox Inbox and Idempotency

## Context
M9F froze DTH-ERA-A Evolutionary Dual-Plane at `0702fab`. M10 decides data topology, SoT, credentials/grants/RLS layers, and persistence classes. Implementation (SQL/roles/policies) is deferred to M11+.

## Binding facts (not optional)
- Supabase `service_role` / privileged secret keys operate with `BYPASSRLS` — RLS does not protect that path.
- PostgreSQL GRANTs and RLS are separate controls: grants gate object access; RLS filters rows for roles that do not bypass RLS.

## Decision
Outbox supports claim/lease, attempts, backoff, idempotency_key uniqueness, correlation, minimized payload refs, states pending/claimed/processed/failed/dead. Duplicate event delivery must not create duplicate lead/case/mail/workflow effects.

## Rejected options
Exactly-once magical delivery; full PII payloads in outbox/DLQ.

## Security impact
Least-privilege DB principals; no general-purpose service_role as normal runtime target; defense in depth (App AuthZ + grants + RLS).

## Privacy impact
Data minimization in queues/audit/traces; staging without production PII; deletion/lineage traceable.

## Operations impact
Postgres-first; single migration authority; evolutionary cutover; no big-bang rewrite of live public intake.

## Migration impact
Additive structures first; public intake remains stable; Ops/local migrations reconciled under one authority.

## Rollback
