# ADR-001 — Canonical Public Runtime

STATUS=ACCEPTED
TRANCHE=DTH-M9  
DATE=2026-08-13  

## Context
Phase-4 dual-plane reality (root public LIVE; packages Ops LOCAL) frozen at M8C `4545c7b`. Architecture must support secure Ops, durable workflows, and future agents without big-bang rewrite of working public intake.

## Problem
Canonical Public Runtime must be decided before implementation so later AuthZ/RLS/workflow work does not accidentally entrench the wrong topology.

## Constraints
- No microservices without need (P20)
- Public intake must not depend on CC/AI (availability)
- RLS ≠ protection from service-role (M8C)
- In-memory controls not production-suitable
- Implementation not authorized in M9

## Options considered
See DTH-M9 evidence report scorecard (Options A/B/C).

## Decision
Repo-root Next.js (and current Vercel Lead/Careers API routes under app/api) remain the canonical public production runtime.

## Why
Already LIVE and stable; migrating into packages/web|api skeletons adds downtime/migration risk without security benefit (strangler).

## Rejected options
Full move to packages/web+api (Option B) now; merging Ops into same deployable as public (Option C) as long-term target.

## Security impact
Keeps public blast radius separate from Ops credentials.

## Privacy impact
Public surface continues to process only intake-necessary data.

## Operations impact
No forced cutover of Checkdomain/Vercel paths.

## Migration impact
Zero immediate public migration; skeletons deprecated later.

## Rollback
Architecture decision can be revised before implementation starts; after impl, follow ADR-specific rollback in implementation tranche.

## Dependencies
M8C baseline; M10 for data/SOT details; M6 does not block this ADR.
