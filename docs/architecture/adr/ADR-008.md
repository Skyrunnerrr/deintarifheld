# ADR-008 — Durable Kill-Switch State

STATUS=ACCEPTED
TRANCHE=DTH-M9  
DATE=2026-08-13  

## Context
Phase-4 dual-plane reality (root public LIVE; packages Ops LOCAL) frozen at M8C `4545c7b`. Architecture must support secure Ops, durable workflows, and future agents without big-bang rewrite of working public intake.

## Problem
Durable Kill-Switch State must be decided before implementation so later AuthZ/RLS/workflow work does not accidentally entrench the wrong topology.

## Constraints
- No microservices without need (P20)
- Public intake must not depend on CC/AI (availability)
- RLS ≠ protection from service-role (M8C)
- In-memory controls not production-suitable
- Implementation not authorized in M9

## Options considered
See DTH-M9 evidence report scorecard (Options A/B/C).

## Decision
Production kill switches are Postgres-backed with audited writes, GLOBAL/DOMAIN/WORKFLOW/AGENT/CASE scopes. Automation fail-closed if kill store unavailable; public intake remains independent of kill store.

## Why
Matches P11–P13; prevents silent automation during control-plane outage.

## Rejected options
In-memory; Redis-only without audit; fail-open automation.

## Security impact
Stops unsafe automation under uncertainty.

## Privacy impact
Control metadata not customer content.

## Operations impact
Ops/worker depend on kill readability.

## Migration impact
Public site must not require kill store to accept leads.

## Rollback
Architecture decision can be revised before implementation starts; after impl, follow ADR-specific rollback in implementation tranche.

## Dependencies
M8C baseline; M10 for data/SOT details; M6 does not block this ADR.
